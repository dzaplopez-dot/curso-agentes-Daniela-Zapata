# Bot de pedidos EFY · Proyecto final Módulo 10

Agente de IA para **EFY Perfumería** (Esencial for you) que atiende por Telegram, recomienda
perfumes inspirados a partir de lo que el cliente recuerda y deja el pedido registrado con el
stock descontado.

## 1. Usuario y problema

**Usuario:** cliente de EFY que escribe por redes pidiendo "algo como Sauvage" o "un perfume
dulce para la noche", y el asesor que responde cada consulta a mano.

**Problema:** el catálogo está organizado por *inspirado en*, *familia olfativa* y *casa*
(80 referencias, todas de 100 ml y $40.000), pero el cliente no conoce esa estructura: recuerda
marcas, no códigos. Cada consulta exige que alguien abra el PDF, busque, cotice y anote el
pedido aparte.

**Beneficio:** el cliente recibe opciones reales del catálogo en segundos, el pedido queda
registrado con su stock y EFY obtiene un panel consultable. Se comprueba con un caso concreto:
"algo como Sauvage para hombre" devuelve dos referencias válidas y un pedido confirmado que
baja el stock de 10 a 9.

---

## 2. Alcance de la primera versión

Incluye:

- Catálogo de **80 referencias** extraído del PDF de EFY 2024 y normalizado a CSV.
- Búsqueda por **inspirado en**, **casa**, **familia olfativa** y **género**.
- Desambiguación cuando la marca tiene varias versiones (Sauvage / Sauvage Elixir,
  Chance / Chance Eau Tendre, Light Blue femenino y masculino, 212, Amber Oud).
- Borrador de pedido con confirmación explícita (SÍ / NO) y descuento de stock transaccional.
- Idempotencia por `(chat_id, msg_id)`: el mismo mensaje no crea dos pedidos.
- Panel HTML con pedidos, stock bajo y ranking de familias y casas.
- 16 pruebas automatizadas (12 de flujo + 4 de la capa de backend).

No incluye: medios de pago, WhatsApp, presentaciones distintas de 100 ml, notas olfativas,
facturación electrónica, envíos.

---

## 3. Herramientas y arquitectura

- **Canal:** Telegram (`python-telegram-bot`).
- **Agente:** Python, máquina de estados; NLU por reglas y **LLM opcional** para extraer
  preferencias (si no hay `LLM_API_KEY`, funciona igual con reglas).
- **Datos:** SQLite local por defecto, con **selector de backend** para Supabase/Postgres
  (`EFY_BACKEND=sqlite|postgres`). Mismo esquema y mismas pruebas en ambos.
- **Salida:** panel HTML estático.

```
Telegram → NLU → orquestador → herramientas → SQLite → respuesta + panel
                                 buscar_perfume · ver_stock
                                 crear_borrador · confirmar_pedido
```

Diagramas editables en `diagramas/*.mmd`, imágenes en `diagramas/*.png`.

**Principio del diseño:** la IA interpreta el mensaje; el precio, el stock y la existencia del
código los resuelve la base de datos. El agente nunca inventa una referencia ni anuncia éxito
antes de guardar.

## 4. Cómo probarlo

Requisitos: Python 3.11+ y conexión a internet solo si se usa el LLM.

```powershell
cd entregable-modulo-10\proyecto
pip install -r requirements.txt
python demo.py --reiniciar
python -m pytest -q
```

`python demo.py --reiniciar` crea la base, carga las 80 referencias y ejecuta una conversación
de principio a fin. Deja la transcripción en `../evidencias/conversacion_demo.txt` y el panel
en `../evidencias/panel.html` (abrir con el navegador).

### Conectar el bot a Telegram

```powershell
cd entregable-modulo-10\proyecto
Copy-Item .env.example .env
# editar .env y pegar el token de BotFather en TELEGRAM_TOKEN
$env:PYTHONPATH = "src"
python -m efy.telegram_bot
```

### Variables de entorno

| Variable | Uso | Obligatoria |
|---|---|---|
| `TELEGRAM_TOKEN` | token del bot | solo para Telegram |
| `LLM_API_KEY` | interpretación con modelo | no |
| `LLM_BASE_URL`, `LLM_MODEL` | endpoint compatible con OpenAI | no |
| `EFY_BACKEND` | `sqlite` (por defecto) o `postgres` | no |
| `DATABASE_URL` | cadena de conexión de Supabase/Postgres | solo con `postgres` |
| `EFY_DB_PATH` | ruta de la base | no |
| `EFY_STOCK_INICIAL` | stock simulado por referencia (10) | no |
| `EFY_PRECIO_DEFECTO` | precio único (40000) | no |
| `EFY_ML_DEFECTO` | presentación (100) | no |

No hay credenciales en el repositorio; solo se documentan los nombres.

### Cambiar a Supabase

```powershell
pip install "psycopg[binary]"
$env:EFY_BACKEND = "postgres"
$env:DATABASE_URL = "postgresql://postgres:CLAVE@db.PROYECTO.supabase.co:5432/postgres"
python demo.py            # crea las tablas y carga el catálogo en Supabase
python scripts/migrar.py  # copia también perfumes y pedidos de la base local
```

El esquema se adapta solo: `BIGINT GENERATED BY DEFAULT AS IDENTITY`, `TIMESTAMPTZ` y
`NUMERIC(12,2)` en Postgres; `INTEGER PRIMARY KEY AUTOINCREMENT` en SQLite. La idempotencia
`UNIQUE (chat_id, msg_id)` funciona igual en ambos.

**Recomendación para el Demo Day:** usar SQLite (sin red ni latencia) y dejar Supabase listo
para el panel en vivo y el acceso por usuario.

## 5. Resultados

- **Pruebas:** 16 de 16 en verde (`evidencias/pruebas_resultado.txt`). Detalle de casos y
  resultados observados en `pruebas.csv`.
- **Conversación real de la demo:** `evidencias/conversacion_demo.txt`.
- **Panel con datos generados:** `evidencias/panel.html` (2 pedidos confirmados, $80.000,
  stock 9 en las referencias vendidas).

Casos del módulo cubiertos:

| Prueba exigida | Resultado observado |
|---|---|
| Caso normal | "como Sauvage para hombre" → 3859 y 2069 · 100 ml · $40.000 · pedido confirmado, stock 9 |
| Dato faltante o ambiguo | "algo rico" pide género y familia; "quiero chance" lista 893 y 3647 |
| Mensaje repetido | mismo `msg_id` dos veces → 1 solo pedido, aviso de duplicado |
| Falla de herramienta | catálogo caído → "no pude consultar… no registré ningún pedido", 0 pedidos |

Casos extra probados: doble confirmación, cancelación, unisex limitado, búsqueda por casa y
normalización de familias (`Aromática`/`AROMATICA`, `Fougere`/`Fougère`, `Maderosa`/`Amaderado`).

## 6. Limitaciones conocidas

1. **Sin stock real.** Se simulan 10 unidades por referencia; el descuento es real en la base
   pero el inventario no viene de EFY.
2. **Precio y presentación únicos** ($40.000 / 100 ml). Están en columnas con default para no
   romper el esquema cuando existan otras presentaciones.
3. **Unisex casi vacío:** solo 3 de 80 referencias. El bot avisa y ofrece alternativas.
4. **Sin notas olfativas** en el catálogo impreso: no hay búsqueda semántica todavía.
5. **Problemas del catálogo fuente:** `PRECICE TERNATIONAL` (ref. 764) y `JEAN PAUL GAUTIER`
   se conservaron tal cual para no inventar datos; ver `datos/revision_datos.md`.
6. **La similitud con la marca original no se certifica.** El bot dice "inspirado en" y no
   compara precios ni calidad con el original.
7. **SQLite en local por defecto.** Supabase está soportado, pero requiere `psycopg`,
   `DATABASE_URL` y conexión a internet; por eso la demo corre en SQLite como respaldo.

## 8. Guion para el Demo Day (5 minutos)

1. **Problema (30 s):** el cliente recuerda marcas, no códigos; el asesor transcribe todo.
2. **Demo (3 min):** "busco algo como sauvage para hombre" → dos opciones → `3859` → borrador →
   `SÍ` → stock 9. Luego "quiero baccarat rouge" para mostrar que no inventa.
3. **Panel (1 min):** pedidos, stock bajo y familias más pedidas.
4. **Aprendizaje y siguiente mejora (30 s):** el catálogo no trae stock ni precios; el
   siguiente paso es conectar inventario real y habilitar otras presentaciones.

Respaldo si falla la red: `python demo.py --reiniciar` reproduce la conversación completa sin
Telegram y deja el panel regenerado.
